## 3. Realer Discord-Smoke

Mit separater Testanwendung, Test-Guild und isolierter PostgreSQL-Testdatenbank mindestens einen repräsentativen Bericht erzeugen.

Zu bestätigen:

- [ ] Statistik-Titel kompakt und korrekt,
- [ ] Spielerfields optisch klar getrennt,
- [ ] GridWords-/QuadWords-Zeilen gut scanbar,
- [ ] mindestens ein `✅`, `❌` oder `⬜`-Mischfall plausibel,
- [ ] Serienblock lesbar,
- [ ] gemeinsamer Block lesbar,
- [ ] Highlights erscheinen als eigene Reportseite/Nachricht,
- [ ] Achievement-Highlight kompakt,
- [ ] Record-Highlight zweizeilig und nicht zerrissen,
- [ ] bei Mehrseitigkeit `Seite x/y` global korrekt,
- [ ] keine echte Discord-Mention wird ausgelöst,
- [ ] keine sichtbare Kürzung oder verlorene Record-Zeile.

### Montag-Startup-Smoke

Idealerweise am Montag innerhalb des Wochenreport-Catch-up-Fensters mit einem bereits erfolgreich persistierten Wochenreport des alten Layouts:

- [ ] Bot starten → letzter fälliger Wochenreport wird einmal in die neue Seitengruppe überführt,
- [ ] alter sichtbarer Report bleibt nicht zusätzlich als verwaiste Dublette bestehen,
- [ ] persistierte Seitenreihenfolge und `Seite x/y` stimmen,
- [ ] Bot erneut starten → keine zweite layoutbedingte Neuerstellung,
- [ ] normaler späterer Scheduler-Tick verändert den erfolgreichen neuen Snapshot nicht erneut.
