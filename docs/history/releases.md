# Releaseverlauf

Diese Übersicht ersetzt den früheren fortgeschriebenen Implementierungsplan als Einstieg in abgeschlossene Releases. Zukünftige Arbeit wird ausschließlich in priorisierten Issues verfolgt.

| Version | Produktiver Umfang | Evidenz |
|---|---|---|
| 1.0.x | Parser, kanonische Ergebnisnachrichten, dynamische Spieler, Tagesstatus, Reminder, Cleanup und Berichte | abgeschlossene Pläne unter [`increments/`](increments/) |
| 1.1.0 | spielbezogene Teilnahme für GridWords, QuadWords oder beide Spiele | [`releases/1.1.0/`](releases/1.1.0/) |
| 1.2.0 | kontextabhängige Ausreden mit persistenter privater Auswahl | [`releases/1.2.0/`](releases/1.2.0/) |
| 1.3.0 | Rekorde, Serienrekorde, aggregierte Meldungen und `/records` | [`releases/1.3.0/`](releases/1.3.0/) |
| 1.4.0 | `achievements-v1` mit 60 Definitionen, Bootstrap, Live-Meldungen und Commands | [`releases/1.4.0/`](releases/1.4.0/) |
| 1.5.0 | UX-/QoL-Erweiterungen bestehender Oberflächen ohne neue Persistenzwahrheit | [`releases/1.5.0/`](releases/1.5.0/) |
| 1.5.1 | kompaktes Wochen-/Monatsreport-Layout und begrenzter Montag-Startup-Refresh | [`releases/1.5.1/`](releases/1.5.1/) |

Version 1.5.1 wurde produktiv aus Commit `832235f1ccc47900494e04fe5535e39194b70354` ausgerollt. Der konsolidierte Dokumentationsstand beschreibt exakt diesen Anwendungscode; spätere reine Dokumentationscommits ändern diese Releaseevidenz nicht.

Die früheren unverbindlichen Platzhalter „Statistik- und Konfigurations-Commands“ und „regelbasierte Kommentare“ waren keine abgenommenen Anforderungen. Eine spätere Umsetzung würde ein neues, ausdrücklich priorisiertes Issue und eine eigene fachliche Entscheidung benötigen.
